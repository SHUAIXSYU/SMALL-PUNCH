# run_017 — 未来五点 ODB 提取和敏感性协议 v1

本文件仅为预案，未执行新的 ODB 提取或 Solver。未来必须在合法计算 Run 中由 MAIN 给真实 ODB 会话分配正式 AgentHub 任务。没有任务或授权时，不轮询并自动启动计算。

## 身份与安全读取

- 五个点只以 `parameter_design.json`、`cae_candidate_manifest.json`、参数 JSON、完整 INP SHA-256、正式 Project ID、未来 queue_id 和实际 Runner 命令绑定。INP 保留历史材料标签 `Q200N01` 与 Heading `Job-1`；这两处标签不代表当前参数或真实 Job 身份。
- 不能仅凭 ODB 文件存在判断成功。要求实际 Queue/历史状态、Datacheck 和 Full 返回码、STA 最终完成、MSG/DAT/LOG 及 ODB jobData 一致；未知、失败或仅 Datacheck 产物不可评分。
- Runner 已退出并释放所有权，无活动目标进程，ODB 无活动写锁、大小/修改时间稳定后才以 Abaqus Python `openOdb(...,readOnly=True)` 读取。疑似遗留锁不清除，不自动恢复。环境内 Python 与 Abaqus Python 分进程，以 CSV/JSON 交接。
- 检查 ODB 实际 Step、实例、参考节点与材料数值，不依据旧材料名猜参数。既有基线 Punch RP 为 `ASM_SPT.1`，必须在每个新 ODB 重新定位唯一匹配的 U2/RF2 历史区；缺失或多义即停止。

## 每个 Job 的必需输出

1. 原始 U2、RF2、时间/增量序列；核对两通道时间配对。分开保存原始量与方向转换量。
2. 压入正方向 F–D：u_m=−U2，F_N=−RF2。不得取绝对值、单独平移零点、乘 2π 或重标载荷。轴对称 RP 总反力按现有提取定义使用。
3. 各保存帧、全部试样积分点的最大 PEEQ，记录位置/帧/单元以及输出位置。它只是**保存帧中的最大值**，不是未保存增量的极值或损伤指标。缺失 PEEQ 不视作 0。
4. STA/MSG 中成功增量数、被拒尝试/cutback 数、最小增量、终止原因、负特征值、严重畸变、接触/数值警告；保留原始日志及匹配位置，不把标题数当独立事件数。
5. Job 状态、Datacheck/Full 各开始/结束/耗时、实际 CPU/GPU；缺失时间填 null。记录 Queue 与 Solver 调用次数、失败和取消、人工等待、CPU 分配核时。
6. INP/ODB/CSV/诊断/日志的路径、大小、SHA-256、提取脚本版本、解释器和来源；源 ODB 前后哈希一致。原始模型与旧 ODB 不写回。

ODB 读取与日志抽取可复用 run_014 已验证脚本，但先审查实际接口和选择范围；不能照搬历史结果。若本轮预案对应源文件发生变化，应新版本冻结而非静默替换。

## 固定实验比较

- 唯一目标是 `loss_contract_identity.json` 绑定的私有 `run017-exploratory-fd-v1`。加载前核对配置、数据和 `inverse/fd_loss.py` 哈希。339 点源曲线与固定 0–1.2 mm 的 241 个原始采样点分别保留。
- 力 N、位移 m；F_ref、权重和网格来自冻结配置。各 FE 历史位移必须严格单调、有限且覆盖整个固定窗口；对 FE 作分段线性插值到同一实验网格，不外推、不自动裁剪、不删异常点、不平滑。
- 计算 L=Σw(F_FE−F_exp)²/(Σw·F_ref²)，并分别报告 √L 和以 N 为单位的 RMSE；L 不等于逐点平均百分比误差。结果注明 `FROZEN_EXPLORATORY_COMPARISON`，不能标为已经实验验证的本构拟合。
- 出现非单调、重复位移、NaN、未知单位或失败结果则保留错误、Loss=null。不得自动排序/平均修复。缺少任一点时可以记录其失败率，不能拼凑完整五点灵敏度。

## 局部敏感性定义

x=ln(σ_y/150)/ln(1000/150)，y=(n−0.02)/0.48；中心 (0.5,0.5)，h=0.2。在固定 u_i 上：

- J_x,i=[F_P03(u_i)−F_P02(u_i)]/(2h F_ref)
- J_y,i=[F_P05(u_i)−F_P04(u_i)]/(2h F_ref)
- 两参数归一化局部敏感性为各列 RMS；敏感性相关性为两列向量的未去均值余弦（明确区别于 Pearson 相关）。
- 对 J/√241 做 SVD，报告两个奇异值、数值秩和条件数。零范数/秩亏时相关性或条件数填 null 并解释，不能凭除零得出强可识别性。
- 条件数>100、|余弦|>0.95 或某方向响应接近数值误差时提示弱可区分；这些是既定工程诊断门槛，不是统计显著性检验。数值误差幅度未确定时，不宣称已排除数值噪声。
- 中心及正负点还报告二阶有限差分以检查曲率。h=0.2 是有限范围割线，可能并非微分极限；本批不自动追加更小扰动求解。
- 可换算物理导数：dF/dσ_y≈F_ref·J_x/(σ_y,center ln(1000/150))（N/MPa），dF/dn≈F_ref·J_y/0.48。原始归一化比较为主。
- 纯离线实现为 `sensitivity_analysis.py`，输入要求已通过身份、质量与固定网格门槛；本轮仅合成测试，不用虚构五组 FE 曲线充当计算结果。

五点仅研究理想化基线附近响应、局部可区分性、成功率与成本。不能证明全域唯一性、最优参数、真实单轴材料曲线或 95% 参数置信区间。

## 质量与继续条件

- Datacheck 失败不得继续 Full；任何非零返回码/失败/未完成立即停止批次，自动重试和重新入队为 0。
- PEEQ 超过 0.9 的材料表覆盖则结果不能作为该材料表充分覆盖的评分；不得自动延长表或重算。达到覆盖边界（距 0.9 不超过 1e-6）先警告并交 MAIN。小于 0.9 仍不能证明时间/空间采样充分。
- 负特征值、严重畸变或新的接触异常要求 MAIN 审查。可只记录探索性诊断，不自动通过科学质量门槛，也不据此自动调整增量、网格或材料。
- 每个 Job 后人工检查再放行下一个；若现有 GUI Runner 会自动连续推进，未来执行时一次只入队一个已授权候选，避免“批内暂停”承诺与 Runner 行为不符。最多五个仍属同一明确授权清单，不能补点/替换点。
- 原始日志/结果均保留；文件冲突、输入哈希变化、Settings变化、所有权/恢复状态不明，立即暂停，不清锁、不覆盖、不绕过 Runner。

## 成本与权限

历史 run_014 同配置总耗时 165 s（Datacheck 36 s、Full 128 s，余约 1 s 为流程间隔）。机械外推 5 个约 825 s=13.75 min，约 3.21 分配核时；这是基线参考，参数变化的收敛耗时未知。

建议未来授权注明 14 CPU、0 GPU、Datacheck+Full、每个唯一输入最多一次、无重试、串行，先 P01 再 P02/P03/P04/P05。可申请 60 min 累计墙钟审查额度；达到额度不放行下一任务。单个作业仍活动时由用户通过 Runner 决定停止，不由脚本杀进程。失败 Datacheck 也占用一次 Job 尝试；实际阶段时间和 CPUh 分开累计。

本轮仅准备，预算批准数=0，queue_id 均=null，求解/成功率/PEEQ/五点敏感性实测值均未产生。当前只能申请首批探索性敏感性计算，不直接申请正式 DE/BO 或全额 48 次预算。
