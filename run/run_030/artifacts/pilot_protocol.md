# run_030 16次探索性反演先导协议（求解前准备）

## 证据边界与版本

- 数值输入：`run030-standard-m0025-hollomon-v1`。源为 run_027 已执行中心输入，`*Static` 保持 `0.001, 1., 1e-12, 0.0025`，`inc=999999`。模型其余物理定义及候选真总应变 Hollomon 生成器不变。中心相邻细化在 run_029 通过；这不证明全域或原四点 Jacobian 已验证。run_025 的历史 BLOCKED 不变。
- Loss：`run017-exploratory-fd-v1`。私有实验源和配置以 `loss_contract_binding.json` 的 SHA-256 绑定。仅用原始 0–1.2 mm 的241个实验点，F_ref=1428.9 N，等权归一化 MSE，FE 到固定实验轴的线性插值，不外推、平滑、删点、移动零点或再做柔度校正。U2、RF2 均按已核验的负号转换为正向压入位移与力。它是探索性目标，不是已验证的 SA508 单轴本构答案。
- 参数域：sigma_y=150–1000 MPa、n=0.02–0.50，E=210 GPa、nu=0.3、塑性表上限0.9。这是 SPT 工程探索范围，不是保留拉伸数据给出的可信先验。历史信息暴露声明保留，封存拉伸文件及派生产物禁读。
- 优化评价集只使用本版本数值控制、相同 Loss 和完整证据的新 FE。run_014/run_017/run_020 等较粗增量结果仅作带来源标签的背景证据；run_027 中心相同增量设置仅作设计和数值锚点，不作为“免费的第九个”共享训练样本或算法排行数据。

## 8+4+4 预算与可复现提案

`parameter_design.json` 已在新 FE 结果前固定8个坐标。归一化坐标为 x=ln(sigma_y/150)/ln(1000/150)，y=(n−0.02)/0.48。I01/I03/I05/I07 用4层中点及固定 y 置换覆盖全域；I02/I04/I06/I08 根据 run_022 的 SPT 低 Loss 点在低 sigma_y、中低 n 区域作局部探索。全域:局部=4:4。序列 I01→I08 交错，首个关口 I01–I04 含两点全域、两点局部。没有按未来新 Loss 重选初始点。

新增唯一 FE 上限16：共享初始8，BO序贯新增4，DE先导新增4。**当前获准入队和求解数量为零**。每次失败尝试也消耗该项预算，零自动重试；重复参数、完整输入/数值契约/Loss 相同且证据有效的缓存命中不产生新 FE，也不自动转让剩余额度。运行前按用户具体授权逐项核验 Queue/Runner，GUI Runner 不具备可靠自动失败停队列，因此一次仅允许一个获授权 Job 可执行。

BO 分支预定使用本机 Torch-GPU 中 scikit-learn 1.7.1 的二维高斯过程：归一化 x、y，Matérn ν=2.5、ARD 两长度尺度，常数核幅值；`alpha=1e-4`、`normalize_y=True`、长度尺度初值(0.25,0.25)、边界(0.05,2)、幅值边界(0.01,100)、10次超参数重启、seed=2301。最小化 expected improvement，固定 xi=0.005；对每次提案使用4096点 scrambled Sobol 候选网格（seed=2301+提案序号）并取 EI 最大者，同值按 x、y 字典序选择。重复容差归一化 L∞≤1e-6；最多20次候选扩展/重提议，仍重复则暂停由 MAIN 审核。每次只用8个共享有效结果和 BO 自身已有结果；若数值证据不合格则停止，不把失败当零 Loss 或可用的训练点。实施时先以该版本的合成用例核验公式、候选唯一性及调用计数，并保存实际库版本与种子；若必须改变规则，另立版本且不追溯改历史分数。

DE 分支不直接调用会触发整代评估的通用优化器。以同8个初始向量作为冻结种群，seed=2302 在求解前产生目标索引打乱顺序及 `rand/1/bin` 三个互异供体索引；F=0.7，CR=0.9，至少一维强制交叉，越界截到[0,1]。只取首4个目标试验，供体始终来自初始种群快照，延迟更新选择，避免先执行的结果改变后续候选。若出现与任何已评估点近重复，重新抽取供体/交叉最多20次，仍重复则暂停；不悄悄消耗更多评估。这只是半代先导，不代表DE收敛。DE只能看到共享8和自身新增结果，不读取 BO 新结果；BO 同理。两分支各自新增上限4，同等信息与 FE 次数比较 best-so-far、失败率、墙钟和分配核时，单种子/极小预算不用于声称算法优越性。

## 每项数值审核与停止

每项先由 AbqJobPilot 公开 Queue/History 及两阶段 LOG/STA 核验 Datacheck 和 Full Analysis 的真实终态、单次尝试、输入 hash、资源和输出目录；存在 Runner 未结束、待恢复或身份不明时停。ODB 只读提取 Punch RP U2/RF2、真实 F–D、最大保存帧 PEEQ、能量、接触、增量与警告，并复核源 hash。完整覆盖固定0–1.2 mm才可评分，不能对单一模型缩短窗口。PEEQ 必须严格低于表末0.9，达到0.85先人工审查裕度；保存帧值不代表所有未保存试算的极值。

失败、缺失/损坏 ODB、材料表越界、阶段状态未知、已接受增量中的负特征值/单元过度畸变/大应变警告或无法解释的明显接触突变，触发**阻塞并暂停后续提交**；Loss=null，人工科研决策，不自动重试或改模型。仅出现在被拒试算的警告，若最终收敛且 F–D/能量证据正常，可记 WARNING 后经 MAIN 审核继续。沿用中心已有类别的一条接受态零力矩提示可按 WARNING 单独审视，不能自动判物理有效。拒绝尝试数>50或占接受增量>10%、PEEQ≥0.85或单 Job 墙钟>20分钟触发人工复核，不自动中止正在运行的 GUI Solver，也不单凭该阈值判定失败。接触转变与局部载荷突跳须在接受帧与增量日志上对齐，不能把被拒试算当作物理路径。

I01–I04 未来完成后暂停：至少有多个输入/输出身份完整且可比较的 FE，需审视参数域两类点的成功率、Loss 地形、补偿迹象、数值告警和真实成本。若系统性问题出现，停止 I05–I08 和 BO/DE；不自动消耗剩余12个名额。8点全部审核后再决定 BO/DE 各4是否值得启用；各分支可在新增2次后再设人工关口。任何“批准16次”计划文本都不构成当前运行授权。

## 成本与科学限制

同数值控制的 run_029 中心实测 Runner 总时长253秒、14核配置；未知域点无法由中心推断。规划按每点4–20分钟，8点约32–160分钟、16点约64–320分钟；14核分配时间对应约7.5–37.3/15–74.7核小时，**不是实测 CPU 使用量或保证上限**。初批记录实际 Datacheck、Full、排队和人工审核时间后再更新预算预测，保留事前估计。参数补偿、理想化夹持、摩擦、仪器校正细节、无损伤窗口和候选本构解释均为科学限制；8+4+4不足以建立严格置信区间、算法优越性或实验本构验证。
